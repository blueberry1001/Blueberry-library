# 高速Implicit Treapの設計と調査

調査日: 2026-10-22。通常版 `blueberry/data-structure/implicit-treap.hpp` は既存で、任意モノイド・作用と非可換な区間積に対応する。ユーザーの追加指定を受け、型やAPIを保てる境界走査の改善を通常版にも反映する。新しい `blueberry/extra-fast/implicit-treap.hpp` は整数のアフィン変換・区間和に用途を絞った選択肢として、「さらに高速なライブラリ」に追加する。

前の依頼で指定された「テストは最低限、速度検証は不要」を継続して適用し、ローカルの比較ベンチマークは行わない。以下の提出時間は公開ランキングの記録であり、本実装の速度や改善率を表さない。

## Library Checkerの公開提出

公開REST APIの `status=AC&order=%2Btime&limit=2` を2問題について取得した。ユーザー重複は除いていない。取得時刻は2026-10-22 03:10:31 UTC。API応答の情報、提出日時、UTF-8ソースのSHA-256は [research.json](measurements/fast-implicit-treap/research.json) に保存した。第三者のソース本文は公開物へ追加していない。

[402977](https://judge.yosupo.jp/submission/402977) と [402526](https://judge.yosupo.jp/submission/402526) は、添字付きpoolで葉と分岐を管理し、葉内を連続配置する。既定の葉容量は512、高さ差の許容は4。アフィン作用にはMontgomery表現を使い、葉の計算や反転をAVX2で処理する。区間作用は分割・再結合せずに下降する。反転の両端断片を交換し、保った経路だけ修復する処理もある。402526はmmapと入力桁数を仮定した読み取り、402977は型付きの制約を持つjudge I/Oを使用する。

[402523](https://judge.yosupo.jp/submission/402523) も葉容量512のropeで、値をuint32、和をuint64に分ける。葉の和・反転・断片コピーにAVX2を使う。問題は長さ固定で値が最大10^9なので、64bit値全般や挿入・アフィン作用まで必要な契約とは異なる。mmap入力と桁数に制約を置いたパーサーも提出時間に含まれる。

[278235](https://judge.yosupo.jp/submission/278235) は要素ごとの固定配列と番兵を使い、両端をsplayして区間を露出する。値はint、和はuint64。木の操作はスカラー処理であり、SIMDヘッダが含まれることだけで木がSIMD化されているとは判断できない。こちらも長さ固定・反転と和のみの問題専用構成で、mmap入力を使う。

## 今回の採用内容

変更前の通常版は `value/forward/backward` と任意の作用を保持し、`prod/apply` にも2回のsplitと2回のmergeが必要だった。split/mergeでは毎回、再利用vectorの作業スタックへ経路を積む。

通常版には、順序を保つprefix/suffixの直接集約と、保存した作業スタック位置から集約を修復する区間作用を反映する。prodは経路用の作業領域を確保せず、applyも木を切り離さない。全区間のprod/apply/reverseはO(1)にし、葉の重複mappingと初期構築の追加巡回も省く。任意モノイド・非可換演算・作用の既定構築不要・Fの等値比較不要という契約は維持し、木の高さに比例するC++再帰も増やさない。

整数専用版では、これに加えて次を採用する。

- 値と和・アフィン作用を整数に固定し、可換な和の逆向き集計を省く。
- 連続poolと32bit添字を使う。既定modのノードは32 bytes、`Mod=0` のuint64版は48 bytes。再利用リストは空きノード内に置く。
- 部分木サイズと反転フラグを同じ32bit語に格納し、独立したフラグ・作業vectorを省く。
- 初期列はCartesian木としてO(N)で構築し、split/mergeは再帰で処理する。
- `prod/apply` は区間を直接下降して処理し、接続を変更しない。反転はsplit/mergeで区間を切り出す。
- 奇数modでは内部をMontgomery表現にし、乗算の剰余を減らす。偶数modでは定数による剰余をコンパイラが簡約できる形にする。既定は998244353、`Mod=0` はuint64の2^64を法とする演算。公開APIの入出力は通常の整数表現。

Treapの下降先は直前の子添字に依存し、連続した複数ノードを同時に演算できる場面が少ない。今回の短い要素単位Treapには、効果が未確認のSIMDや手書きasmを加えていない。チャンク化すればSIMD対象を増やせる一方、分割・占有率調整・断片反転の実装が増えるため、今回の短いTreapとは別の設計になる。

## 制約と検証の扱い

操作はランダムな優先順位を仮定して期待O(log N)。最悪O(N)で、再帰スタックも木の高さに比例する。固定seedで再現できる擬似乱数を使うため、敵対的な入力に対する最悪時間・最悪スタックの保証はない。poolの再確保を伴う挿入には確保済みノード数に比例する処理があり、コピーと列への書き出しも線形となる。

任意のモノイド、非可換集計、任意の作用が必要な場合は通常版を使う。今回は比較測定を省略しているため、既存版やFastestより速いとは断定しない。正しさは対象APIの小規模な境界・愚直比較と公式verifyを中心に確認し、実行結果はPRの検証記録で示す。

ローカルではGCCのgnu++20とClangのgnu++23で固定seed 1のvector愚直比較、GCCのASan/UBSan、公式ドライバ2本の小さい入力による照合が成功した。Mod=0/1/998244353/2^31に加え、最終のGCC確認では奇数合成数15と奇数上限2^31-1も対象に含めて成功した。新しいAPI文書の最小mainもコンパイル・実行している。make check / make verify / make docsの全体ローカル実行と速度測定は省略し、公開前のCIは通常の設定を維持する。

通常版は既存のlegacy-treapと、非可換な文字列連結・既定構築できない作用型を使う追加テストを実行した。GCC gnu++20、Clang gnu++23のNDEBUG構成、GCC ASan/UBSanの各seed 1で、計6実行すべて成功した。追加テストは0/1/2/17/65要素について反転・非可換な作用合成を組み合わせ、全区間を愚直比較する。通常版・専用版の文書例も両方コンパイル・実行している。

初回の統合CIではC++の4構成と153単体テストが成功した後、追加random testの公開一覧への登録漏れで停止した。[失敗ログ](https://github.com/blueberry1001/Blueberry-library/actions/runs/39717108563)を保持し、生成元のスクリプトで一覧を更新して整合性を再確認した。未実行の公式ケースを成功扱いにはしていない。
