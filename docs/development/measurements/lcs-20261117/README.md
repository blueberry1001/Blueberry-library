# 最長共通部分文字列の高速化

基準は main `179d99a39514b3321a163218273b394cdf7e1203` の `longest-common-substring.hpp`（Git blob `4495e2b236b62bfdaeaf0883ee4722039a3d7096`）。短い入力が長い入力の接頭辞か接尾辞なら最長長に到達しているため、`string_view` 比較で即答する。一般入力は ACL の SA-IS で suffix array を作り、Kasai の LCP 計算と最大候補の探索を統合し、LCP 配列の確保・後続走査を省く。バイト値、入力寿命、空文字列、同長候補の不定性、最悪 O(N) 時間・空間は維持する。

[Library Checker 最速提出 #406239](https://judge.yosupo.jp/submission/406239) は AVX2、接頭・接尾の一致による早期確定、文字集合の判定、seed を使った探索と suffix array への fallback を使う。提出は専用 I/O、実行環境、文字範囲が異なり、同じ条件で再実行していない。seed 探索は未移植であり、最速との差は未解消。

Windows 11、Intel Family 6 Model 183、論理 CPU 4 固定、Clang 18.0.3 / MSVC 19.43、C++20、`-O2 -DNDEBUG` 相当。入力生成と I/O は計時外。長さ10万の2文字列、各2回の呼び出し合計を warmup 1回、順序を入れ替え7回計測した中央値（ms）。接尾辞ケースのみ片側5万文字。共有 CPU の他の負荷は排除できない。

| 入力 | Clang 変更前 | Clang 変更後 | MSVC 変更前 | MSVC 変更後 |
| --- | ---: | ---: | ---: | ---: |
| 26値の乱数 | 35.559 | 32.843 | 39.470 | 36.082 |
| 2値の乱数 | 35.216 | 35.084 | 40.079 | 37.743 |
| 全バイトの乱数 | 34.949 | 31.325 | 41.545 | 38.229 |
| 全文字一致 | 11.223 | 0.009 | 12.229 | 0.009 |
| 周期7のずれ | 9.815 | 9.107 | 11.220 | 9.384 |
| 長い方の接尾辞と一致 | 24.186 | 0.004 | 26.964 | 0.004 |
| 最後の1文字だけ不一致 | 29.595 | 27.137 | 35.284 | 33.334 |

`result.json` に各回・コンパイル・比較テストの結果、`result-fused-only.json` に早期確定追加前の結果を保存した。測定ドライバは各入力で変更前後の回答長の一致を確認し、さらに NUL と高位バイトを含む5万件を愚直解と比較した。`run.py` は Windows のローカルツールチェーンと ACL パスを示す。再実行時は測定ファイルを別ディレクトリへコピーし、それらのパスを環境に合わせて変更する。

追加の独立検証では、バイト集合 `{0,255}` の長さ0〜7の文字列について全65,025組を愚直解と比較し、一致した。テストは `audit_exhaustive.cpp.txt`。
