# 矩形割当の最短増加路（2026-11-17）

既存の Hungarian 法は各反復で全列の slack とポテンシャルを更新する。候補は未確定列を連続配列に置き、増加路の探索が終わってから確定済み列のポテンシャルを更新する。実装は自作し、ACL に同等 API はない。

[KACTL WeightedMatching](https://github.com/kth-competitive-programming/kactl/blob/main/content/graph/WeightedMatching.h) の CC0 原本（Git blob `89b806ee27604e8ebc0a487c957705a6dc4f91b2`）も同じコンパイラと行列で比較した。KACTL は行列を非 const 参照で受け、独自の距離更新順を使う。測定アダプタでは行列を変更せず、総費用と割当の妥当性を検査する。Library Checker の最速提出の現在順位とソースは取得できておらず、KACTL をその提出と同一視しない。

初期候補の詳細は [全試行](results.json)、[旧実装](baseline.hpp.txt)、[初期候補](candidate-initial.hpp.txt)、[KACTL 原本](kactl-reference.hpp.txt)、[ドライバ](bench.cpp.txt)、[実行手順](run.py.txt) を参照。Windows 11、Intel64 Family 6 Model 183 Stepping 1、Clang 18.0.3 の MSVC ABI、`-std=gnu++20 -O2 -DNDEBUG`、単一 CPU に固定。入力生成と I/O を除き、割当構築・結果検証を含む。ウォームアップ2回、実測7回を交互順で行った。表は反復合計の ms 中央値（旧版→候補→KACTL）。

| 入力 | N×M | 反復 | 旧版 | 初期候補 | KACTL |
| --- | --- | ---: | ---: | ---: | ---: |
| 一様乱数 | 400×400 | 4 | 29.196 | 15.840 | 14.898 |
| 7種類の乱数 | 300×300 | 2 | 41.972 | 23.311 | 19.830 |
| 全値0 | 200×200 | 2 | 11.432 | 5.801 | 5.234 |
| 列番号 | 150×400 | 2 | 13.746 | 9.216 | 7.006 |
| 一様乱数 | 80×800 | 10 | 1.070 | 0.518 | 0.401 |

上記は試作単体の結果であり、型と値域の確認を含む最終ヘッダの時間ではない。分布や環境で差は変動する。assert 有効で N≤7 の乱択を全割当と比較し、費用と割当の妥当性も確認した。同率の最適解の選択は元 API で保証しないため一致を要求しない。最初のビルドは、比較用 KACTL 原本のローカル変数が `-Wshadow -Werror` に引っかかって失敗した。原本を改変せず `-Wno-shadow` を指定した再実行で、[失敗結果](build-failure.json) も保持する。ピークメモリ、Linux、公式入力と最速提出の同条件比較は未測定。

公開 API の前提を狭めないため、最終版では符号付き組込み整数のうち N≥64、M≤8N、かつ全費用の絶対値が `max(T)/(16(N+1))` 以下のときだけ、この経路に入る。それ以外は従来の Hungarian 法を用いる。高速経路の増加路は最大 N 行を通り、各行で加える費用差の絶対値は高々 2B（B は上記の最大費用絶対値）である。完全二部グラフの双対ポテンシャルと未割当列の値0を使うと、探索開始時の列ポテンシャルは −2B 以上0以下。したがって候補距離、ポテンシャル差と最終費用の絶対値は 16(N+1)B 未満に収まり、追加の符号付きオーバーフローを防げる。浮動小数点、unsigned、比較・加減算のみを備える独自型、ガードを超える値は旧経路のまま。

単純な `vector<bool>` から byte 配列への変更も調べたが、同じ環境の7回中央値は乱数400×400で 27.863→29.958 ms、全値0の200×200で 10.648→11.963 ms と回帰したため不採用。[条件と全試行](../assignment-byte-20261117/results.json) を保存する。

5×7 は旧経路を使用する。80×800 は値域の確認に対し割当本体が短く、旧版との差は測定範囲が重なる。[全サンプル](final-results.json)、[ドライバ](final-bench.cpp.txt)、[実行スクリプト](final-run.py.txt) を保存した。KACTL は値域ガードがないため、公開ヘッダと同一のオーバーフロー保証を意味する比較ではない。

公開ヘッダのテストは N=63/64/65/80 の乱択部分行列を全割当と比較し、同率、矩形、short/int/long long、ガード境界の内側と外側の正負、unsigned、double、比較・加減算だけを持つ独自型を確認した。符号付き最大値に基づくガードの境界付近で正負の値を混ぜ、入力値を1つだけ境界外へ変えた旧経路も照合した。Windows Clang 18 の gnu++20/23（`-Wshadow -Werror`）と MSVC C++20 でそれぞれ seed 1、17、731 が成功した。[最終のコンパイル・テストログ](validation.json) と [追加前](validation-initial.json) を保存。符号付き最大幅やユーザー定義型の全可能な入力は列挙できていない。Linux GCC / Clang、Library Checker 公式ケース、`make test` / `make verify` / `make docs` はローカルでは未実行。

## 横長と値域外の回帰

初版は N=64・M=100000 でガードの全走査が上乗せされ、範囲内 24.790→31.578 ms、末尾だけ範囲外 23.564→33.791 ms と回帰した（各2反復）。[初版の全試行](wide-results.json) と [当時の公開ヘッダ](header-before-ratio.hpp.txt) を保存。横長で M>8N の場合は値域を走査せず従来経路を使うようにし、N=64・M=100000 の範囲内は 21.817→22.968 ms、末尾だけ範囲外は 27.101→27.075 ms となった。[比率ガードの全試行](ratio-results.json)。

M≤8N では、範囲判定を行内で集約し、範囲外があった行で走査を止める案を評価した。旧版・最終ガード・集約前ガード・KACTLを同一バイナリで交互に測定。N=64・M=512・125反復の範囲内は 6.330→4.652→5.672→2.603 ms、末尾だけ範囲外は 6.478→8.556→9.321→2.602 ms。集約後も末尾まで走査してから戻る入力では、旧版に対し約32%の回帰が残る。先頭だけ範囲外では旧・新ガードとも測定範囲が重なった。M=513 は比率ガードで旧経路を選ぶ。全サンプル・分布・範囲・入力生成を [記録](guard-results.json) した。

追加テストでは N=64/65/100 の全面乱数を各40件ずつ旧 Hungarian と照合し、N−1回の再割当を必要とする増加路、M=8N と M=8N+1、値域外の先頭・末尾も確認した。入力を点検する事前サンプリング案は採用していない。
