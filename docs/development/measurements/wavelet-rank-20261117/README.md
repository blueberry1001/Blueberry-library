# Wavelet Matrix の順位表と共通分岐

[前回の比較](../wavelet-20261117/README.md)で、範囲頻度には入力が疎な場合でも大きい整数表が必要な点と、Nyaanとの速度差が残った。今回は元の公開APIを保ち、候補ごとに同じ入力で構築・操作・プロセスの peak working set を測った。

最終候補は、異なる値が4096以下の場合は高速な整数表を保持し、それを超える場合は値の存在bitと64bit単位の累積個数で圧縮する。連続値域では前回と同様に表を保持しない。元の整数表は最大約4 MiB、bit列・累積個数の表は `sizeof(RankBlock) == 16` の環境なら最大約256 KiB。種類数が少ない場合は速度を優先して整数表を残すため、メモリ削減は得られない。構築中は一時領域を含むため、保持量だけではpeakを表せない。

範囲頻度では上下端の圧縮順位が分岐する段のrankを一度だけ求め、左右それぞれの残りを数える。同じ値の上下端は0を返す。popcountは標準C++を使い、特定CPU命令を必須としない。256種類まで整数表を残す案、全てbit列とする案、順位表だけ・分岐段だけの案も比較した。4096閾値を越える場合はメモリと構築を削減しつつ、少ない種類数では整数表のアクセス速度を残す選択である。閾値は実測に基づく経験的な選択であり、あらゆる入力・環境に最適とは限らない。

## 同条件での比較

Windows 11、Intel Family 6 Model 183、MSVC 14.43.34808およびWindows Clang 18.0.3、C++20、`-O2` 相当・`NDEBUG`、N=200,000、Q=100,000。候補と実行順を入れ替え、warmup 1回・測定7回の中央値。各実行のchecksumは一致した。CPU固定はせず、同時に動く他セッションやCIの負荷の影響を除外できないため、小さな差を確定的な速度差として扱わない。peak working set は Windows の `GetProcessMemoryInfo` で取得し、入力・クエリ・一時配列・ランタイムも含む。単体の構造体メモリではない。

| compiler・分布 | 構築 ms 旧→最終 | kth ms 旧→最終 | 値域頻度 ms 旧→最終 | peak MiB 旧→最終 |
| --- | ---: | ---: | ---: | ---: |
| MSVC・20bit乱数 | 16.49→15.08 | 18.09→18.36 | 26.70→22.66 | 15.53→11.78 |
| Clang・20bit乱数 | 14.51→13.14 | 22.48→22.80 | 34.36→29.61 | 15.53→11.77 |
| MSVC・広い値域に32値 | 5.80→5.57 | 4.40→4.39 | 6.10→5.82 | 14.57→14.61 |
| MSVC・広い値域に4096値 | 12.18→11.30 | 11.90→11.63 | 15.55→15.35 | 15.18→15.18 |
| Clang・広い値域に4096値 | 10.37→10.08 | 14.42→14.68 | 19.21→18.75 | 15.18→15.18 |
| Clang・全幅乱数 | 16.53→16.76 | 23.34→23.87 | 41.00→40.68 | 11.53→11.52 |

4096値のMSVC範囲頻度は、整数表を256種類までしか残さない案では15.83ms、4096種類まで残す最終案では15.35ms。閾値を広げるとこの入力のpeakは約3.7 MiB増えた。値が一致する端点だけの問い合わせはコンパイラがループごと除去できる場合があり、実競技全体の速度比には使わない。11分布と全sampleは [`portable-results.json`](portable-results.json)、途中案は `portable-results-v1.json`～`v5.json` に残す。

Nyaanのbit幅指定版との直接比較は、Nyaanに合わせて非負20bitに限定し、双方に BMI2・POPCNT を指定した Windows Clang 18 / C++20 / `-O2` の別測定。N=200,000、Q=100,000、warmup 1回・各5回の中央値は以下。Nyaanの値・CPU前提と、任意符号・bit幅を受ける公開APIの違いがあり、Yosupoの公式時間でもない。第三者原本の出典・CC0と `__lg` のドライバ側補助については[前回記録](../wavelet-20261117/README.md)を参照。

| 20bit乱数 | 構築 ms | kth ms | 任意値域頻度 ms | 幅1の値域頻度 ms |
| --- | ---: | ---: | ---: | ---: |
| 直前の公開版 | 14.21 | 17.05 | 23.54 | 12.09 |
| 最終候補 | 11.91 | 17.23 | 20.37 | 11.14 |
| Nyaan | 15.14 | 16.88 | 18.30 | 16.97 |

Nyaanの任意値域頻度にはなお差が残る。構築・操作を除く入力の読み書き、公式入力、ピークメモリを含むend-to-end比較は未実施。全sample、hash、flagsは [`results.json`](results.json)、初回案は [`results-v1.json`](results-v1.json)。

## 検証と再現

最終ヘッダと追加した乱択テストは、Windows上のMSVC 14.43（C++20/C++latest）とClang 18（gnu++20/gnu++23）で、各seed 1・2・17の全12回が成功した。符号付き最小値・最大値、辞書外、表の穴、0/63/64のbit境界、255/256/257/4095/4096/4097種類を含む。Nyaan直接比較と各性能比較も候補間checksumが一致した。結果と全コマンドは [`test-results.json`](test-results.json)。別担当の静的確認でも分岐段・bit境界に明確な問題は検出されなかった。LinuxのGCC/Clang、sanitizer、公式verify、広範囲な既存ライブラリとの統合テストは、この記録の対象ではない。

測定時のコードと候補を `*.hpp.txt` に、ドライバとrunnerをこのディレクトリに保存した。対象headerのraw SHA-256は `f4719ecf8fb0ad717718d389b9fd06ef131c7f8e66ddd2ae23cc06bca87b3596`、乱択テストは `be49e0a9eb23011e7f6c24c8f7e1c6847dd03e7aa72539640bf88bdc026cd75f`。ログ内のhashと一致する。環境固有の絶対パスはrunner内で指定しており、他環境では変更が必要。リポジトリルートから `python docs/development/measurements/wavelet-rank-20261117/generate.py` で `current.hpp.txt` から各候補を生成した後、同ディレクトリの `portable.py` でportable比較、`run.py` でNyaanとの比較、`test.py` で最終候補の乱択検証を再実行できる。出力は `.build/wavelet-rank-study/` に置かれる。
