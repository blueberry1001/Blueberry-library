# Hopcroft–Karp の高速化

比較元は main `4089073325823283c4558aaf7ce48a9070200f24`、ヘッダ blob `9b5c588e9f436d40836bb689220bcf96d2a3a93f`。空辺列は初期化の直後に返す。長さ1の増加路を最初に貪欲処理し、マッチ数が `min(L,R)` に達したら最大と確定する。残りは従来どおり非再帰の Hopcroft–Karp を使い、BFS は空き右頂点を最初に見つけた時点で終了する。対応・被覆の選択は従来どおり未規定。`pairs()`、最小頂点被覆、空グラフ、多重辺、深い経路を維持する。

## BFS の停止条件

左頂点の距離 d の頂点を取り出すとき、FIFO キューは距離 d−1 の全頂点を処理済みで、到達可能な距離 d の左頂点をすべて発見している。空き右頂点が見つかると最短増加路は d+1。距離 d の残りの左頂点を探索して新しく発見できる左頂点は距離 d+1 以降であり、その層は長さ d+1 の増加路には不要。DFS は距離が割り当てられた頂点を使い、各辺自体は従来どおり検査する。最悪計算量 O((L+R+M)√(L+R)) と非再帰の性質は変わらない。

[最速提出 #396318](https://judge.yosupo.jp/submission/396318) は固定サイズ配列、双方向 CSR、高速 I/O と、右側からの層探索・反復増加を使う。入力上限や I/O が異なるため、提出時間をこの汎用 API の同条件測定とはみなさない。提出コードは転載せず、既存の最短路層を保持する方式を改善した。

## 計算部分の比較

Windows x64、Intel Family 6 Model 183、Clang 18.0.3 / MSVC 19.43、C++20、`-O2 -DNDEBUG` 相当、論理 CPU 8 固定。入力生成・I/O を除き、同一入力の構築3回を1測定とした。warmup 1回、順序を交代した7回の中央値、単位 ms。共有 CPU の他負荷は除外できない。`results-3way-v3.json` は元版、貪欲初期化のみ、最終版の全試行を収録する。

| L=R=100,000 のグラフ | Clang 元版 | Clang 最終 | MSVC 元版 | MSVC 最終 |
| --- | ---: | ---: | ---: | ---: |
| 各左頂点から乱数8辺 | 129.871 | 99.613 | 132.059 | 93.195 |
| 一対一の100,000辺 | 4.716 | 1.652 | 8.056 | 2.361 |
| 50,000より長い増加路を含む連鎖 | 12.378 | 9.360 | 13.727 | 9.364 |
| 辺なし | 2.226 | 0.494 | 2.829 | 1.321 |

CSR 構築中に `offset_` を一時 cursor に使い、後で復元する候補も同じ条件で測った。Clang の一対一入力では貪欲案 1.711 ms に対し 2.125 ms、MSVC の同じ右頂点への集中入力は 8.636 ms に対し 9.669 ms だったため採用しなかった。`results-3way-v2.json` に全試行を残す。実メモリ使用量は測定していない。

## 公式生成入力

Library Checker 問題集 revision `73876f1cbcf082d2b22722924b924d3d65a2f00e` の44入力を生成し、全入力の SHA-256 が公式 `hash.json` と一致した。旧版・最終版とも各入力のマッチ辺の実在、左右頂点の重複なし、全辺を覆う同数の頂点被覆を確認した。これは matching と cover のサイズ一致による最適性検証で、公式 checker を実行したという意味ではない。

Clang、CPU 8、各ケースを warmup 1回と7回測った中央値。コンストラクタのみを計時した結果と、入力読み込み・検証・プロセス起動を含む経過時間は次のとおり。末尾2例では構築中央値が回帰し、試行間の幅も重なる。

| --- | ---: | ---: | ---: | ---: |
| max_random_00 | 44.20 | 38.18 | 195.52 | 175.94 |
| cycle_00 | 418.00 | 384.13 | 551.14 | 545.25 |
| unique_matching_02 | 427.80 | 404.59 | 565.81 | 544.06 |

25,000個の固定 seed 小グラフ、4×4単純二部グラフ全65,536通りで、愚直な部分集合 DP と旧版・最終版のマッチ数、選択辺、最小頂点被覆を照合した。50,000頂点の深い増加路、空辺列、多重辺は公開テストでも検査。最終ヘッダのランダム・境界テストは Clang / MSVC × C++20 / 23 で通過。Linux GCC、公式 checker、競技サイトへの提出、最速提出との同条件実行は未実施。

独立監査では 5×4 と 4×5 の単純二部グラフ全2,097,152件、ランダム多重グラフ30,000件を、部分集合 DP・マッチ辺・逆引き・最小被覆・コピーとムーブで検証し、Clang / MSVC × C++20 / 23 の4構成で一致した。試験とログは `independent-audit/` にある。

`reproducibility.tar.gz` に source 原本、各候補、測定ドライバ、公式生成器と Apache 2.0 ライセンス、各実行ログ・失敗した候補のログを保存する。展開後、`run3.py` は `candidate.hpp` を最終版または `candidate-v2.hpp` に差し替えて再実行できる。`official_run.py` は使用環境の Windows SDK とコンパイラパスを指定しているため、必要に応じて変更する。`archive.sha256` はアーカイブ全体の SHA-256。
