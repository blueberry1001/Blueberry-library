# Minimum Spanning Forest の高速化

基準は main の `minimum-spanning-forest.hpp`（Git blob `5d268ef0cd0e993e7e6b1c93519028c96cb1eb47`）。Library Checker の [最速提出 #364954](https://judge.yosupo.jp/submission/364954) は調査時 25 ms で、入力された32-bit非負重みの辺を4パスの基数ソートで並べ、連結後に打ち切る Kruskal 法を使っていた。固定配列・入力制約に特化した高速 I/O も使う。同提出のソースをコピーせず、符号付き・非連結・汎用重みを含む既存契約に合わせた。

辺が8192本以上、整数重みが32-bit値域内のとき、値域幅4095以下なら数え上げ、広い値域なら4パスの基数ソートを行う。広い値域では M<2N の場合は重みと辺番号のキー、それ以外は端点を含む構造体を並べ替える。64-bit の値が32-bit値域から外れる場合と、その他の型は比較ソートに戻す。全頂点が連結になれば処理を終える。DSU には ACL を使う。

## 同一条件の比較

Windows 11、Intel Family 6 Model 183 Stepping 1、論理 CPU 8 に固定。Windows Clang 18.0.3 と MSVC 19.43、C++20、最適化有効、`NDEBUG`。同じ `vector<tuple<int,int,long long>>` と同じ driver で入力を生成し、生成・入出力を計時から除く。構造の生成、並べ替え、DSU と結果生成は計時に含める。各ケースはウォームアップ1回・計測5回、実行順をローテーションし、返る総費用と採用辺数を確認した。値は中央値 ms、回数は一つの計測中の関数呼び出し数。共有マシンの負荷は分離できておらず、数%の差は不確実。

| 入力 | 回数 | Clang 旧 | Clang 新 | MSVC 旧 | MSVC 新 |
| --- | ---: | ---: | ---: | ---: | ---: |
| N=100000, M=500000、32-bit全域乱数 | 3 | 245.835 | 61.577 | 248.616 | 54.249 |
| 同、星型 | 3 | 246.911 | 66.942 | 226.119 | 52.758 |
| 同、半分の頂点が孤立 | 3 | 226.007 | 52.484 | 239.728 | 47.446 |
| N=100000, M=100000、連結 | 5 | 62.608 | 21.268 | 61.575 | 15.505 |
| N=100000, M=500000、重み {-1,0,1} | 3 | 43.434 | 33.504 | 36.831 | 27.975 |
| 同、32-bit値域外を含む44-bit重み | 3 | 234.685 | 246.315 | 262.152 | 251.476 |
| N=1000, M=8192、32-bit乱数 | 50 | 29.877 | 9.697 | 30.751 | 8.161 |

44-bit 重みの Clang は約5%遅く、値域を確認してから比較ソートへ戻る費用がある。高速化は普遍的ではない。密グラフの広い値域では16-byteの一時配列を2本使い、従来の辺番号配列よりメモリが増える。ピークメモリは今回個別に計測していない。

最速提出と同じ「端点付きの辺を基数ソートする」考えを用いて、同契約の入力・計時条件で別途作った試作も比較した。32-bit全域乱数の中央値は Clang 51.485 ms、MSVC 49.527 ms と新実装より速い。試作は独自 DSU を使うため、実際の提出コードとの直接比較ではなく、差の原因も単独では確定していない。汎用ライブラリとしての速度差を埋める余地が残る。

## 検証と再現

固定 seed の独立な Prim 法との比較6000件に加え、空・自己ループ・非連結、重複重み、辺数8191/8192/8193、値域幅4095/4096、M=2N の前後、符号付き32-bitの両端と範囲外、符号なし64-bit、浮動小数点、独自の比較・加算型を確認した。Windows Clang / MSVC × C++20 / C++23 × debug / release-header の8構成で通過。テスト側の assert は release-header でも有効。公式問題ケースおよび Linux GCC はローカルでは未実行。

`reproducibility.tar.gz` に比較・テストのソース、各回の JSON、試作と失敗した最初のテストビルドのログを収める。展開後 `python run.py`、`python test-run.py` で再実行できる。Visual Studio・SDK・Clang のパスは手元の環境に合わせて変更する。ログ内の絶対パスも測定当時のもの。アーカイブの SHA-256 は `archive.sha256` に記録する。
