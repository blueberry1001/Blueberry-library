# Static Range Mode: rollback と端点別単調走査（2026-11-17）

既存の offline Mo では頻度ごとの二重連結リストを区間の伸縮ごとに更新する。候補は左端をブロック分割し、各ブロックでは右端を単調に伸ばしてから左側のみを一時追加・巻き戻す。最大頻度と代表値は右側の状態を保存して復元する。全部同じ区間で const 要素同士の比較・等値判定が可能ならその区間だけを処理し、それ以外の型は従来通り可変の値コピーで圧縮する。左端または右端が高々8種類なら、端点ごとに反対側を単調に伸ばす。返す代表位置の選択は元から未規定であり、空区間は `{-1, 0}` のまま。任意の比較可能・コピー可能な型、順序と等値性の要件、バッチ入力、O(N+Q) 領域を維持する。

一般の場合は幅 `max(1, floor(N / sqrt(Q)))` のブロックを使う。右端の前進とブロック切替の初期化は合計 O(N sqrt(Q)+Q)、左側の追加と巻き戻しも O(N sqrt(Q)+Q)。座標圧縮・query ソートを含め O(N log(N+1)+Q log(Q+1)+N sqrt(Q)+Q)。少数端点の経路は高々8回の全配列走査、同一区間は一度の区間ソートで収まり、この上界を超えない。Q=0 は即時返却する。

## 参考実装と比較範囲

- [maspypy の Library Checker 検証例](https://maspypy.github.io/library/test/2_library_checker/data_structure/static_range_mode_query.test.cpp) は rollback Mo で一時追加を記録・取り消し、最大頻度と値を復元する。提出時の型・入力形式・I/O と、本ライブラリの汎用型、空区間・代表位置契約は異なる。独自実装でありソースの転載ではない。
- [Nyaan の Mo](https://github.com/NyaanNyaan/library/blob/master/misc/mo.hpp) は query 数も考慮して幅を決める。旧実装の幅だけを `N/sqrt(Q)` に変えた第3候補も、同じ入力・コンパイラで別途測った。
- [suisen の Range Mode](https://github.com/suisen-cp/cp-library-cpp/blob/main/library/range_query/static_range_mode_query.hpp) はブロック対の事前計算によるオンライン問い合わせであり、全クエリを受け取る本 API と契約が違う。ACL に対応操作はない。
- Library Checker の現在の最速順位・提出ソースは取得できなかった。上記外部実装との同条件直接測定も実施しておらず、最速との性能差は不明。

## 棄却・修正した試作

初回の rollback のみは全区間を繰り返す Q=100000 で 9.26→34.04 ms に回帰した ([results-v1.json](results-v1.json))。同一区間の結果再利用を加えても 8.35→12.17 ms と回帰が残った ([results-v2.json](results-v2.json))。その後、同一区間を一度だけ処理する版でも単調な固定端 query に約4〜5倍の回帰があり ([results-v3.json](results-v3.json))、少数の端点を単調走査する経路で解消した ([results-v4.json](results-v4.json))。各段階のソース・実行スクリプト・結果は保存しており、これらを最終測定と混ぜない。

## 検証と未実施事項

ベンチドライバは N≤60 の全半開区間、固定 seed のランダム配列、同率、空・重複 query、bool・文字列・ユーザー定義型、端点1/2/8/9種類を変更前・変更後・愚直解で照合した。独立レビューで const な値同士の `==` が使えない型のコンパイル互換性を検出し、最適化経路を条件付きに修正した。非 const 参照同士の `==` のみを持つ型で、空 query、空区間、1件、同一区間多数、固定端と一般経路を追加検証した。公開ヘッダを使う `tests/random/sequence-batch-four.cpp` は Windows Clang 18 の gnu++20/23、assert 有効・無効、seed 1/17/731 の12通りを実行した ([public-test.json](public-test.json))。最初の release ビルドはローカルにある ACL が `-I` から読み込まれて unused-variable 警告を `-Werror` として失敗したため、`-iquote` と `-isystem` でヘッダ探索順を分離して再実行した。初回の失敗は [public-test-initial.json](public-test-initial.json) に保存した。互換性修正前のヘッダ・測定・テスト記録は `public-header-v5.hpp.txt`、`results.json.v5.txt`、`public-test.json.v5.txt` として別保存した。

Linux GCC / Clang、公式問題、`make test`、`make verify`、`make docs` はこの Windows ローカル調査では未実施。WSL は起動時 `Wsl/E_ACCESSDENIED`、GCC と make は PATH 上にない。公開ヘッダを直接使う計測版と、保存された変更前・幅のみ変更版は namespace 名だけを変更して同一バイナリへ組み込んだ。
