# Triangle Enumeration の CSR 化（2026-11-17）

次数順の有向辺を、頂点ごとの可変長配列から prefix sum を使った連続配列に変更する。元の辺の順序で格納し、列挙する三角形と callback の順序を維持する。公開 API、単純無向グラフの前提、最悪時間 O(N+M√M) と作業領域 O(N+M) は変えない。ACL に相当する機能はない。

## 実装の比較

[maspypy の実装](https://github.com/maspypy/library/blob/main/enumerate/triangle.hpp) は次数順の有向グラフを作ってマークを使う。辺の重複除去と callback による早期停止があり、単純グラフ入力で全件を列挙する本 API とは契約が異なる。[hitonanode の実装](https://hitonanode.github.io/cplib-cpp/other_algorithms/enumerate_triangles.hpp.html) は頂点ごとの配列と明示的なマーク解除を使う。本実装は各頂点 ID をマークに書き込むため解除走査は不要。コードの転載はない。

Library Checker の最速提出の順位・ソースは取得できず、これら外部実装との同条件の実測は行っていない。過去の [graph-batch-two](../../../../benchmark/graph-batch-two.md) の隣接行列版との比較は別環境・別入力であり、今回の改善率として流用しない。

## 正当性と再現性

assert 有効の比較で N≤5 の全単純グラフと各 N≤15 の固定 seed 乱択100件を三重ループと比較し、旧版・候補の callback 引数を全件記録して列ごと一致を確認した。各 callback 引数を非 const 参照で受け取り、書き換える組合せも旧版と照合した。乱択では入力辺と端点の順序も変更した。測定の全ケースでも callback 回数・順序付きハッシュが一致した。公開ヘッダを使う既存ランダムテストに辺順の乱択と callback 引数の書換え、再入、例外伝播の検証を追加した。

旧版のスナップショットは git HEAD の元ヘッダとテキスト一致し、候補は namespace 名だけ変更すると公開ヘッダとテキスト一致する。最終測定ドライバは公開ヘッダを直接 include する。[最終の全試行・ビルド](results.json)、[初回](results-v1.json)、[空辺早期 return 前の公開ヘッダ直接測定](results-v2.json)、[参照引数の互換性修正前](results-v3.json)、[旧版](baseline.hpp.txt)、[候補](candidate.hpp.txt)を保存した。初期候補は callback が引数を書き換えた場合に旧版と異なる問題が独立レビューで見つかったため、範囲の終端と第3引数の寿命を修正し、最終版を再測定した。修正前の候補測定は参照書換えを扱わず、正当性の根拠にしない。初回の runner と `validation-v3.json` が参照する実行ログは上書きされており、完全再現できない。CPU 負荷やコンパイラ、分布で結果は変化する。完全グラフの測定範囲は重なっており、小さな差を一般化できない。

公開ヘッダを使う `tests/random/graph-batch-two.cpp` は Windows Clang の gnu++20 / gnu++23 と MSVC C++20 で成功した。[コマンド・終了コード](validation.json)と各構成の実行ログを保存した。

Linux GCC / Clang、Library Checker 公式ケース、`make test` / `make verify` / `make docs` はこの Windows 測定では未実施。
