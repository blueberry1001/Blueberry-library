# Dual Segment Tree の遅延フラグ

main `4089073325823283c4558aaf7ce48a9070200f24` の `dual-segment-tree.hpp`（Git blob `9fc5b1bb0fe07c0104642692ee232851c4f710a8`）を基準とし、遅延ありを表す `vector<bool>` を1要素1バイトの配列に変更した。プロキシ参照によるビット操作を減らす。構築・操作の計算量と F の等値比較不要という契約は変えず、遅延合成の順序も保つ。フラグ用のメモリはおよそ `base/8` バイトから `base` バイトに増える。

[最速提出 #409050](https://judge.yosupo.jp/submission/409050) は短く難読化されたコードに64操作単位の処理を含む。[上位提出 #269952](https://judge.yosupo.jp/submission/269952) は固定容量、固定法998244353と AVX2 を使う幅8の木を用いる。これらはオンラインの任意作用・任意型に対応する公開 API とは条件が異なる。元コードの直接比較や競技サイトへの再提出は行っていない。

## 構造単体の測定

Windows 11、Intel Family 6 Model 183、論理 CPU 12 に固定。Clang 18.0.3 `-O2 -DNDEBUG` と MSVC 19.43 `/O2 /DNDEBUG`、C++20。長さ262144、30万操作、32bit整数の affine 写像で演算は unsigned 32bit の折り返し。構築、操作、最後の全要素取得を含め、入力生成と I/O は除く。ウォームアップ1回、5回測定を実装ごとに順序を入れ替え、中央値を表示する。共有マシンの他の負荷は除去できない。単位は ms。

| 操作 | Clang 基準 | Clang byte | MSVC 基準 | MSVC byte |
| --- | ---: | ---: | ---: | ---: |
| ランダム区間更新70%・一点取得30% | 101.72 | 97.49 | 125.47 | 94.48 |
| ランダム区間更新・一点取得が半々 | 86.54 | 78.00 | 93.50 | 70.43 |
| ランダム区間更新のみ | 141.05 | 124.93 | 145.92 | 105.34 |
| 一点取得のみ | 11.49 | 10.52 | 6.96 | 5.17 |
| 区間更新・一点取得・一点代入・一点更新を均等 | 68.06 | 64.07 | 65.54 | 46.78 |
| 長さ32未満の短区間と一点操作 | 26.38 | 24.64 | 17.34 | 15.08 |

取得時に遅延を伝播せず、葉から根へ直接作用させる案も測定した。小さい区間から大きい区間へ18回重ねて更新し、同一点を100万回取得した場合、MSVC では byte 版の 10.56 ms に対し直接作用案は 30.77 ms、旧版も 15.94 ms だった。未伝播の作用を毎回再適用するため、この案は不採用とした。push の子処理統合・境界ノードの重複排除も試したが、コンパイラや操作分布により byte 版を下回るケースがあり、不採用とした。全測定値は `results*.json` と `hot-results*.json` に残す。

## 公式ケースと再現

Library Checker 問題リポジトリ revision `73876f1cbcf082d2b22722924b924d3d65a2f00e` の公式生成器で19入力を生成した。旧版・byte 版・不採用の直接作用案それぞれについて、19入力の生成結果および出力の SHA-256 が公式 `hash.json` と一致した。公式 checker 自体は実行していない。最大3ケースを旧版・byte・直接作用の3版で各3回、プロセス起動と標準入出力を含めて実測した中央値は 1261.6 / 1216.9 / 1272.7 ms。個々の値は約1089〜1472 ms とばらつきが大きく、この結果だけでは優劣を断定できない。

`delivery-results.json` は公開候補そのもののランダム・境界テストで、Clang / MSVC、C++20 / 23、assert 有効 / 無効の8構成が成功した。空区間、サイズ0〜130、非可換作用、一点代入、コピー・ムーブ、S/F の既定構築不可、F の等値比較不要、`bool` と `std::string` を含む。公開対象のテストコードは `tests/random/dual-segment-tree-byte.cpp`。Linux GCC・公式 checker は CI で確認する。

実行コマンド、各回のログ、各候補、公式生成器と Apache 2.0 ライセンスは `reproducibility.tar.gz` に保存した。展開したディレクトリで `python run.py` 等を使い、Windows コンパイラ・SDK と ACL のパスを環境に合わせる。`results-mixed.json` は測定途中で試作の参照修飾を変えた初回記録であり、Clang と MSVC で試作の版が異なるため採用判断に使わない。公式初回の `hash.json` 転記失敗も `official-initial-failure.txt` に保存した。アーカイブの SHA-256 は `archive.sha256` に記載。
