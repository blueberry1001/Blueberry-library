# Clique Enumeration の候補配列再利用（2026-11-17）

`enumerate_cliques` の再帰呼び出しごとの候補配列を深さ別に再利用し、最大出次数 D が 1 以下なら再帰を使わず列挙する。後者は単純無向グラフで次数・頂点番号順に辺を向けたときの性質に基づく。いずれも空でない全クリークを一度ずつ出力し、既存実装と同じ callback の順序、参照の寿命、例外伝播と再入性を保つ。時間とメモリの上界は変わらない。ACL に相当 API はない。

## 既存実装との比較調査

Library Checker で 10 ms の提出例 [417440](https://judge.yosupo.jp/submission/417440) を確認したが、提出ソースを取得できず、その時点の最速順位も確認できなかった。提出時間を同一環境比較として扱っていない。[maspypy の実装](https://github.com/maspypy/library/blob/main/enumerate/clique.hpp) は最小次数除去と全頂点の隣接行列を用い、O(N²) メモリを必要とする。本ライブラリは疎グラフにも対応する既存の O(N+M+D²) メモリ契約を維持した。ソースの転載はなく、外部の最速コードとの同条件実測は未実施である。

## 実測

Windows 11、Intel64 Family 6 Model 183 Stepping 1、Clang 18.0.3、MSVC ABI、`-std=gnu++20 -O2 -DNDEBUG`。同一バイナリに変更前後を組み込み、同じデータ・callback・入力順で交互に実行した。プロセスと子プロセスは同一 CPU affinity 0x1 に固定。計測は入力生成後、グラフ構築・全列挙・各クリークのハッシュ計算を含み、出力 I/O は含まない。比較版のハッシュと callback 回数はすべて一致。表の時間は記載回数分の合計 ms の中央値（最小–最大）。初回 1 回をウォームアップし、5 回測定した。

| グラフ | N | 辺数 | 1 回の callback 数 | 反復 | 変更前 ms | 変更後 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 完全 | 17 | 136 | 131071 | 30 | 142.497 (140.619–147.792) | 43.781 (43.211–46.116) |
| ランダム p=1/4 | 110 | 1466 | 6159 | 80 | 32.365 (32.319–33.719) | 22.305 (21.867–23.536) |
| ランダム p=1/2 | 65 | 1027 | 23687 | 20 | 26.969 (26.588–27.436) | 16.080 (15.893–16.752) |
| cycle + 23 飛び辺 | 20000 | 39977 | 59977 | 15 | 68.580 (66.596–68.860) | 65.204 (64.424–67.278) |
| 星 | 30000 | 29999 | 59999 | 20 | 54.167 (53.096–54.345) | 53.367 (52.614–58.641) |

小入力と疎グラフはウォームアップ 2 回、11 回測定した。N=0（30 万反復）は 1.129→0.954 ms、N=1（20 万反復）は 17.465→17.476 ms、N=2 の 1 辺（10 万反復）は 19.923→19.620 ms、N=8 のパス（3 万反復）は 23.295→22.490 ms。疎 N=20000 は 67.305→66.811 ms、星 N=30000 は 59.804→57.073 ms で、測定範囲は重複する。これらは観測値であり、わずかな差の一般化はできない。

プロセス全体の peak working set は完全グラフで約 3.6 MiB、疎 N=20000 で約 5.8 MiB、星で約 6.4 MiB。初期化やランタイムも含み、ライブラリ単独の追加メモリではない。実測入力・全サンプル・checksum・ピーク値・実行コマンドは [測定ログ](measurements/clique-reuse-20261117/) に保存した。

## 検証・再現性

assert 有効の変更前後比較で N≤5 の全単純グラフ、各 N≤10 の乱択 100 件を部分集合全探索と照合し、変更前後の callback 列も完全一致した。辺順と端点順の乱択、callback 中の再入、および一般経路と D≤1 経路での例外伝播も確認した。公開ヘッダを使う独立テストは Windows Clang の gnu++20 / gnu++23 と MSVC C++20 で成功した。

最終測定の candidate snapshot の SHA-256 は `bc1c9c46e079c21ec8e3ea06a18c74318d56c24048788d219b4d1cc4a9e875c1`。公開ヘッダとは改行コードだけが異なり、テキストは一致する。`results.json` と `small-results.json` が最終測定、`build.json` と `public-test.json` が最終ビルド・検証結果である。`*-v1.json` / `*-v2.json` / `small-results-v3.json` は開発中の結果。最初のビルドは Windows の `min` / `max` マクロ衝突で失敗し、`NOMINMAX` をドライバに追加して再実行した。失敗ログも保存した。初回候補の生成スクリプト原本は保存できていないため、該当測定の完全再現性は限られる。

Linux GCC / Clang、`make check`、`make test`、Library Checker の公式ケースを含む `make verify`、`make docs` はこの調査では未実施。競技環境や別コンパイラでの性能、公式時間制限内での動作はこの Windows 計測からは判断できない。
