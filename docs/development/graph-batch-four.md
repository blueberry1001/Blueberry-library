## 採用判断

2026-09-18 に非ACLの3機能を追加しました。各APIページの一次資料リンクから複数実装を調査し、
外部コードを転載せずアルゴリズムを再実装しています。

| 機能 | 調査した候補 | 採用 |
| --- | --- | --- |
| 最大独立集合 | Nyaan の分枝探索、Luzhiled のランダム貪欲、半分全列挙 | N≤40 の厳密な半分全列挙。入力に依存しない指数上界 |
| 根付き木同型 | spaghetti-source の子ラベル整列、Nyaan の木ハッシュ | 整列した子クラスの完全ベクトル。衝突なし・反復走査 |
| クリーク全列挙 | Luzhiled の近傍部分集合、maspypy の最小次数DFS | 次数向き付けと候補絞り込み。O(N²)隣接行列を回避 |

## 同一環境での候補測定

`benchmark/batch-four-graph.cpp` の独立した比較用候補を GCC 13.3.0、`-std=gnu++20 -O2 -I.`、
WSL2 Linux x86_64 上で測定。固定seed `20260918`、同じ入力、各3回。
公開提出の測定値との比較ではありません。ウォームアップは設けず全測定値を保存しました。
生ログ: [CSV](graph-batch-four-benchmark.csv)、[環境](graph-batch-four-environment.txt)。

| 入力 | 採用中央値 / 最小 (ms) | 比較候補中央値 / 最小 (ms) |
| --- | --- | --- |
| 根付きパス4000頂点 | 0.367334 / 0.349040 | 括弧列全保存 6.916860 / 4.705600 |
| 24頂点、辺確率1/4 | 0.022443 / 0.021731 | 全頂点subset DP 15.472000 / 13.182400 |
| 20頂点、辺確率1/2 | 0.012501 / 0.008406 | 全部分集合clique DP 1.495570 / 1.479490 |

各候補の結果チェックサムは一致しました。比較用候補のメモリは順に O(N²)、O(2^N)、O(2^N)、
採用方式は O(N)、O(2^(ceil(N/2)))、O(N+M+D²)。小さい測定であり一般的な速度比を保証しません。
クリーク数が指数的に増える入力では callback を含めた出力自体が律速します。

## 検証

固定seedランダム350ケースで最大独立集合・全クリークを部分集合全探索と比較、
根付き木同型を完全括弧列表現と比較します。空グラフ、40頂点の空辺、20万頂点パスも確認。
GCC / Clang の gnu++20 / gnu++23 全4構成でランダム・境界テスト成功。`-DNDEBUG -Wall -Wextra -Werror` の単独・重複includeも全4構成で成功。
公式問題は各 `verify/graph/*.test.cpp` に登録し、公式checkerで3対象すべて成功しました。
直列1回、公式ケース全体の実行合計 / 最大ケースは clique 0.178190 / 0.018467秒、
MIS 0.205769 / 0.024043秒、tree isomorphism 3.452799 / 0.499132秒です。
1回の測定なので性能改善の根拠にはしません。
[測定JSON](graph-batch-four-verification.json) にcompiler・flags・入力digest・ケース数を保存しています。
