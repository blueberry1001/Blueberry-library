## 変更内容

`FastInput` / `FastOutput`の整数変換を改善した。
`contest-fast-io.hpp`の`scan`、`print`、`LL`、`O`からもそのまま利用できる。
公開API、対応型、オーバーフロー検査、失敗時の戻り値、64 KiBのバッファ容量は維持する。

- little-endian環境のバッファ内では8桁をまとめて変換・範囲検査する。
  読み込んだ範囲内だけを参照し、短い残りやバッファ境界は従来の1桁処理へ戻す。
- 1桁の整数は直接処理し、短い入力に対する一括変換の準備を省く。
- 出力は型の最大桁数分を一度確保する。64bit以下は既存の2桁表で変換し、
  128bitは10^19単位に分けて広い整数の除算回数を減らす。
- 128bitの符号付き最小値・符号なし最大値、長い先頭zero、
  不正tokenからの復帰、EOF、pipe、FILEエラーを引き続き扱う。

変更したライブラリは`blueberry/utility/fast-io.hpp`。
公開仕様は[Fast I/O]({{ '/blueberry/utility/fast-io.hpp.html' | relative_url }})、
測定条件・採否・全ログは[測定資料](measurements/fast-io-throughput/README.md)、
LC上位と著名ライブラリの方式は[調査資料](measurements/fast-io-throughput/research.md)にまとめる。

## 性能測定

Library CheckerのMany A+Bと128bit版の公式入力・期待出力を使い、
変更前と採用版を同じコンパイラ・オプション・CPUで交互に測定する。
入力単体、出力単体、入力から出力までを分け、通常ファイルとpipeを確認する。
符号付き・符号なし64/128bit全範囲の固定seed入力もPython整数のoracleと照合する。

GCC 13.3、gnu++20、`-O2 -DNDEBUG`、CPU 2に固定した5回の中央値は次のとおり。
global APIで、公式`max_random_00`を通常ファイルから読み、結果を書いてflushするまでを測った。

| 公式入力 | 組数 | 変更前 | 採用版 | 速度比 |
| --- | ---: | ---: | ---: | ---: |
| Many A+B / i64 | 1,000,000 | 68.113 ms | 45.463 ms | 1.50倍 |
| Many A+B 128bit / i128 | 500,000 | 140.802 ms | 55.925 ms | 2.52倍 |

最終比較の3,168実行は全て期待出力とbyte単位で一致した。
64bitの桁数ランダム入力をGCC・直接API・pipeで読む条件には、入力単体で約18%、
入力から出力までで約5%の回帰が残る。global API、型、入力分布ごとの結果を測定資料に記載した。

標準変換関数だけで64bitを出力する案、4桁ずつ出力する案も試したが、
GCCで回帰したため採用しなかった。8桁の変換を試す回数も減らし、
0だけのケースに残っていた回帰に対して1桁の直接処理を追加した。
これらの途中結果とソースのsnapshotも測定資料へ残す。

## 検証

`tests/random/fast-io.cpp`へ、型ごとの境界・不正token・128bit乱択を追加した。
固定の大容量バッファ境界テストはseed 1で実行し、各seedでは乱択とtoken復帰を確認する。
公式verifyは従来のMany A+Bドライバとテンプレート形式のドライバを使う。

- GCC 13.3 / Clang 18.1、GNU++20 / GNU++23で追加テストを各20seed実行し、成功した。
  ASan/UBSanもseed 1の固定バッファ境界を含めて成功した。
- `make test`の149 unit tests、116ライブラリ文書・117実行例、
  ヘッダ116本・verifyコード154本のコンパイルが成功した。
- `make check`は乱択テスト中に実行環境の中断を受けた。
  完了済みログを保持し、乱択テスト58本を各20seedで再開して全て成功した。
  `-DNDEBUG`でのヘッダ単独・重複includeも成功した。
- 公式ドライバ6本を全ケース各3回で実行し、成功した。
  初回はPATHに`oj`がなく起動できなかったため、環境を修正して再実行した。

初回の中断・起動失敗と、再開後の結果はどちらも
[検証資料](measurements/fast-io-throughput/validation/)に保存した。
公式実行の時間はassert有効・NTFS入力を使う検証環境の値であり、性能表の比較には混ぜない。
